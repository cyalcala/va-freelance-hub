The two-item publication ceiling then selects from that retained work. ## Concrete first slice and acceptance

1. In `domain-ats-discovery.ts`, preserve the Workable response's item membership and minimal native facts **before** filters, date normalization or admission/publication slicing. Keep the native posting ID/shortcode, exact tenant/endpoint, original posting field and explicit remote/location evidence; record malformed entries as held/rejected evidence. Bind storage to the observed response and its actual status. Reuse the corrected strict Workable parsing leaf from the 0054 repair instead of retaining a second creation-date fallback. A new generic evidence framework or a copy of the large Greenhouse module is unnecessary.
2. Route that representation through existing `persistDiscoveryObservation` → `storeRawObservation(... requireCompletePayload: true)`. Fail closed on malformed/lost storage acknowledgement. Keep the observation pending until all item positions have an acknowledged candidate/sighting or a durable reason. Do not mark processed after caught failures. A bounded complete raw envelope is a durable pending prerequisite, not proof that every opening was qualified or published.
3. Extend `processAndRefineCandidate` only where needed to return durable outcomes and preserve distinct provider opening identities. Treat the current coarse fingerprint as a linkage hint, not authority to discard another shortcode/URL. Changed material facts on an existing identity use the existing digest/delta and clock functions; they must not reset first observation/publication dates. Initial work may remain pending while this reconciliation is incomplete.
4. Add a native/local-libSQL writer test using the actual existing lake schema and injected client. Cases: more than 20 entries; four eligible openings with publication cap two; malformed/missing-date entry; two distinct IDs with identical employer/title; changed remote/date facts at the same URL; failed or lost storage acknowledgement; crash/restart; duplicate retry; and oversized payload. Assert all observed positions are durably accounted for before any public exposure. Keep 304/no-body and unknown upstream pagination coverage explicitly incomplete. No live credentials are needed for this slice.

The first code changes belong in `scripts/lake/domain-ats-discovery.ts` and its existing tests, `scripts/lake/ingest-to-lake.ts` plus its caller tests, and a narrowly shared Workable parsing leaf if needed. Existing `lake-shared.ts` strict storage and pure delta/coverage functions should remain the authorities. Add schema only if a real writer test demonstrates an outcome cannot be represented by existing raw/candidate/sighting records; do not invent a second queue first.
